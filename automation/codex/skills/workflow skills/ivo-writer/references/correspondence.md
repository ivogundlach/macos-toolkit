# Correspondence mode

Use these rules for emails, replies, messages, letters, and other direct correspondence.

## Target-language gate

- Before drafting, declare `Target language: <language> (<sender/date or explicit instruction as evidence>)` in user-visible commentary immediately preceding drafting. Do not insert it into the communication. A general bilingual form may be `Target language: <language> for <part>; <language> for <part> (<evidence>)`.
- Explicitly named draft language overrides thread evidence; the language Ivo happens to use to instruct Codex is not evidence.
- Otherwise resolve from the established language of the inspected case/thread as a whole. Ivo's most recent authored message can establish a switch. Use the most recent counterparty-authored message only as tiebreak when no clear case language exists; conflicting mid-thread switches require asking. Exclude quotations, signatures, disclaimers, and auto-generated boilerplate; short human replies count.
- New outbound thread: use explicit instruction or inspected prior correspondence with recipient; otherwise ask. Any unresolved/conflicting evidence requires asking before draft creation.
- Apply the resolved language and thread-established register to all authored text. Existing reply subjects/prefixes stay verbatim; new subjects use the target language. Institutional correspondence defaults formal; German defaults formal Sie with a conventional German salutation/sign-off. Quotations, proper nouns, legal citations, and identifiers may remain verbatim.
- Verify the full human-authored draft before creation. If an existing persisted draft mismatches, stop before sending/deleting and ask before modification; never recreate a draft with attachments or user edits.

## Voice

- Be short, direct, concrete, and neutral-polished. Short does not mean incomplete.
- Remove conversational filler such as "I hope this finds you well."
- Start with the recipient's name followed by a comma, use `Hi [Name],` for friendly personal outreach, or skip the greeting when that is more natural.
- Use `Good morning,` or `Good afternoon,` when no recipient name is known and the context supports it.
- Prefer short declarative sentences. Avoid compound or run-on sentences.
- Use plain acceptance language such as "sounds good to me" instead of service-tone phrasing such as "I'd be happy to."

## Meaning and context

- Answer the proposal or main question first.
- Preserve useful logistics and contact-channel context: location, travel timing, deadlines, timezone, phone availability, meeting constraints, and iMessage/RCS/WhatsApp limits.
- Preserve timing boundaries such as "until August" when they explain the constraint.
- If the message contains multiple small asks or confirmations, answer each one explicitly and in order.
- Preserve identifiers the recipient needs, including student IDs, case numbers, account numbers, dates, and room numbers.
- Use one short context paragraph followed by one direct ask when the recipient needs context before acting.
- Avoid sounding demanding when asking for an exception, accommodation, or manual processing.
- Do not invent commitments, dates, phone numbers, facts, promises, explanations, or emotions.

## Formatting and closing

- Use bullets or numbering for more than two genuinely separate questions or items. Do not over-bullet simple administrative emails.
- A brief thanks is appropriate for real personal outreach or friendly logistics.
- Close with a farewell that carries meaning. Default to a specific thanks naming what the recipient actually did or is about to do, such as `Thanks for your time,`, `Thanks for the help,`, `Thanks for looking into this,`, `Thanks for the quick reply,`, `Thanks for the message,`, or `Appreciate it,`. Match it to what really happened in the thread; never thank someone for something they did not do.
- `Best,` is the fallback, not the default. Use it only when nothing in the message supports a specific closing, such as a purely informational note with no ask and no favor received. Do not repeat it across consecutive drafts to the same recipient.
- When the message ends on a clear ask or a settled logistic, no farewell at all beats a generic one.
- For every email draft, do not add "Ivo" as a manual signature. Ivo's mail clients insert his signature automatically.
- Never use `Sincerely,`, `Warm regards,`, or `Thanks in advance.`
- Use a bracketed placeholder only while a genuinely missing value blocks completion. Remove all placeholders before final delivery unless Ivo explicitly wants an incomplete template.

## Apple Mail compatibility

The unattended Apple Mail runner reads this file directly as its canonical correspondence source. Changes here therefore affect both interactive drafting and the background runner after validation.
